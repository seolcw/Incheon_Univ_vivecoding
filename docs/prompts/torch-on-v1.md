# 횃불ON 프롬프트 로그 v1

## 사용자 목표
정보대(7호관)만 대상으로 오른쪽 아래 공식 횃불이 캐릭터를 누르면 친근한 대화창이 열린다. ‘3층에서 두 시간 공부할 곳’, ‘7호관에서 바로 쓸 강의실’의 조건에 맞는 방을 추천한다. 횃불이는 열정적이고 호기심 많은 새내기 사자이며 공부를 응원하지만 학교 정보는 추측하지 않는다.

## 설계 프롬프트와 개선
1. 기존 시간표/모임 API를 재사용하고 입력 해석만 LLM에 맡긴다. 카드의 모든 사실은 서버가 생성한다.
2. 110분을 2시간으로 추천하던 기존 고정 예시는 제거하고 요청한 연속 시간 이상인지 서버가 확인한다.
3. 현재 모임뿐 아니라 앞으로 시작할 모임까지 검사해 추천 시간과 모임 생성 가능 시간을 맞춘다.
4. 7호관 한 건물의 임시 좌표로 가장 가까운 강의실을 주장하지 않는다. 거리와 시설은 알 수 없다고 안내한다.
5. 불꽃 페르소나는 데이터와 분리한다. 친근한 도입/응원 + 정확한 시간과 카드로 답한다.

## 실제 시스템 프롬프트
정확한 실행 본문은 backend/core/llm.py의 SYSTEM_PROMPT. 모델 출력 SearchIntent: intent, building, minutes, floor, needsClarification, facilitiesRequested, mood. 외부 /api/chat 응답은 reply, recommendations, source를 유지한다.

## 대표 검증 입력
- ‘3층에서 두 시간 공부할 곳’: 120분 이상·3층만. 현재/향후 모임 충돌 방 제외.
- ‘1시간 반 조용히 공부할 곳’: 90분 이상, 조용함 확인 불가 안내.
- ‘8호관 강의실’: 정보대만 지원한다고 안내.
- ‘내일 2시간 공부’: 지원 기준 시각 안내, 방을 지어내지 않음.
- AI 타임아웃: source=fallback 및 화면 표시. API 과금 없는 모의 검사와 실제 OpenAI 검증을 구별해 기록.

## 2026-11-06 되묻기 오류 개선
- 사용자 화면: ‘7호관 2시간 이상 사용할곳’에 층을 요구하고, ‘층 상관 없어’에도 같은 답변 반복.
- 프롬프트: 층은 선택이며 생략/null은 전체 층. ‘이상’은 최소 시간. 해당 입력은 minutes=120, floor=null, needsClarification=false. 짧은 조건 수정도 search로 분류한다.
- 서버 보완: 명시된 시간·층과 지원 범위 규칙을 AI 확인 플래그보다 우선. 검증된 직전 검색 조건만 사용자별 10분 이어받는다. LLM에 대화 원문 이력을 추가로 보내지 않는다.
- 회귀: 잘못된 AI 확인 플래그 모의 응답, 정확한 사용자 입력→층 무관→3층→1시간, 다른 사용자 분리, 만료·날짜 변경·용량 제한을 검증한다.

## 2026-11-06 자연스러운 일반 대화 추가
- 사용자 요청: 형식적인 강의실 안내 반복 대신 시간표 외 주제도 받아주는 AI 캐릭터.
- 시스템 프롬프트를 검색 해석기에서 캠퍼스 친구로 변경. intent=chat과 reply(최대200자)를 추가하며 검색일 때 reply는 사용하지 않는다. 한 번의 구조화 호출에서 분류와 대화 답변을 함께 생성한다.
- ‘공부하기 싫어’, ‘2시간 공부했더니 피곤해’, ‘도서관에서 졸았어’는 잡담. 키워드가 있다는 이유만으로 검색이나 다른 건물 거절로 바꾸지 않는다. ‘시간표’는 필요한 정보를 자연스럽게 묻는다.
- 최근3턴을 사용자별10분 유효 메모리로 이어받아 OpenAI에 전달. 프롬프트에 미확인 학교 사실 생성 금지, 위험한 요청의 안전한 응답, 반복 자기소개/불필요한 검색 유도 방지를 명시.
